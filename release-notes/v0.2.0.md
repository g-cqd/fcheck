# fcheck 0.2.0 (from 0.1.2)

Wave 1 of the analyzer release train (analyzerkit tag `analyzerkit-wave-1`): fcheck on analyzerkit's shared
foundations, with five rule fixes (analyzerkit 0025). Findings are identical to 0.1.2 on maintastic and every g-cqd
package.

## Flags

- Added: `--exclude-path`, `--include-regions`, `--exclude-regions`, `--report-new-since` (it requires
  `--only`), `--quiet`, `--verbose`, `--timings`, and `--define`: with it, or the configuration's
  `defines`, only the `#if` clauses active under those conditions are read (analyzerkit 0059, ADR-0029).
  Without one every clause is read, as before.
- Renamed, with the old spelling accepted until wave 3 and printing a note: `--include-tests` → `--include-regions
  test,generated`.
- Removed: none.

## Exit codes

- An `error` finding fails the run without `--strict`.
- An invalid configuration or baseline exits 78, an unwritable baseline 74, and a run that read nothing 70.

## Report

- Added, optional for a reader (ADR-0017): `tool`, `version`, `runNotes` (`{code, severity, message, count, paths}`), `skippedFiles` (`{path, reason}`, the reason one of `notIndexed`, `changedSinceBuild`, `unreadable`, `degraded`), and `timings` with `--timings`.
- Nothing removed or retyped; `schemaVersion` stays 1. SARIF, baselines and fingerprints are byte-identical.
- `cacheNote` stays, and is also in `runNotes`.
- SARIF: under `--relative-to`, locations are relative to `SRCROOT` (analyzerkit 0044).

## Configuration

- `defines` and `platforms` (shared keys) are read: with a define, only the active `#if` clauses are read, and
  they are part of the cache salt.
- The shared `.swift-analyzers.json` (top-level shared keys, one section per tool) is read beside the tool's own file, found from a subdirectory too, nearest first (ADR-0021).
- A configuration with an unknown or repeated key now exits 78; before, it was ignored.
- `exclude` follows ADR-0008: a glob matched against the path relative to the configuration's directory.
- `includeRegions` and `excludeRegions` are read.
- `Package.swift` manifests and scripts that a build phase runs are the `script` region, left out unless
  `--include-regions script`.

## Cache

`--cache-path` names a root directory now (ADR-0011): facts sit in sharded files under `<root>/facts/<workspace>/`, keyed by file metadata then content, and memory-mapped. Payloads are protobuf. A tool keeps 512 MiB at most and evicts the least recently used workspaces first. A v1 cache file at the same path is replaced. The default root is `~/Library/Caches/<tool>` on macOS and `$XDG_CACHE_HOME/<tool>` (or `~/.cache/<tool>`) on Linux. On a CI runner, delete the old v1 cache files once; the tool would replace them anyway.
The old `~/.cache/fcheck` is no longer read; delete it. Each round of the corpus-acquirer pass is cached in its own
workspace, so a warm run reads it too.

## Findings that may appear

- Only with `--define` or `defines`: findings in the clauses those conditions make active, and none from the
  others. Without a define nothing changes.
- `leak-on-exit` through a wrapper of a wrapper: a function that returns what another acquirer returned acquires
  too, to any depth, and a body that is one acquiring expression returns its handle (probes F1, F1b).
- `leak-on-exit` "when it is reassigned at line N": a handle lost when its variable acquires another (probe F2).
- `replace-not-durable` after a `rename` that is followed only by a call with "flush" in its name (`flushLogs()`), or
  by an `fsync` of the file's own descriptor. Only a flush of the directory settles a rename now (probe F5).

## Findings that may disappear

- `leak-on-exit` where the handle goes to a function whose name only starts like a non-owning prefix (`login` is not
  `log`, `issue` is not `is`) (probe F3).
- `leak-on-exit` from a call that shares a corpus acquirer's name but not its arity or its base's type
  (`door.open()` when `Store.open()` acquires) (probe F4).
- Findings in `Package.swift` manifests and build-phase scripts, which are the `script` region now.
